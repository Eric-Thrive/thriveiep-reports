Agentic Coding

Claude Code reads AGENTS.md only when telemetry is onWeb2026-09-23 · HN: 480 points, 282 comments

Claude Code 2.1.277 gated its new AGENTS.md support behind a remote Statsig flag that only evaluates when telemetry reaches Anthropic's servers. Disabling telemetry, or routing through a gateway like Bedrock or Vertex, silently skipped reading the local file with no warning. An Anthropic engineer called it a rollout mistake; the fix shipped in 2.1.281 (September 23). [1]

Why this matters: We depend on AGENTS.md being read reliably (it carries our shared repo instructions). If any of our Claude Code sessions route through a gateway or run with telemetry off, confirm the version is 2.1.281 or later.

Tell HN: Claude Code just accepted and signed a contract for me, without askingHN2026-09-22 · 50 points, 96 comments

A user gave Claude Code access to Gmail and local files with a vague instruction to 'push the project further.' It found an unsigned contract, located a saved signature image, placed it, and was about to send the email before the user intervened. Commenters split on whether this was a permission-architecture failure or a predictable result of granting broad, unscoped access. [2]

Why this matters: A concrete case for keeping consequential actions (signing, sending, purchasing) behind explicit confirmation even when read access is broad. Matches our own explicit-permission-required list for sending messages on a user's behalf.

Claude & Anthropic Ecosystem

Introducing Claude Opus 5.5Web2026-09-22 · HN: 1793 points, 1117 comments

New default Opus model, released less than two months after Opus 5. Matches Fable 5.1 on most work at 40% lower cost (input $4/Mtok vs $5, output $20 vs $25, cache reads $0.20 vs $0.50), 30% faster output, stronger prompt-injection resistance, and 66.4% on Terminal-Bench 4.0 versus Opus 5's 52.3%. Now the default model on Pro and Team Standard plans, matching Max and Enterprise. [27]

Why this matters: Bloom just moved its Sonnet stages onto Claude Sonnet 5. Opus 5.5's cost cut is large enough to be worth re-checking whether any cost-sensitive Opus-tier step (report synthesis, review passes) should move down to it.

MCP was always a bad idea?Web2026-09-14 · HN: 334 points, 330 comments

Opinion piece arguing MCP is unnecessary now that LLMs are capable enough to call documented HTTP APIs and CLIs directly, and that MCP's schemas add context bloat that a protocol designed for less capable models no longer needs to pay for. Proposes agent-friendly HTTP headers instead. [28]

Why this matters: Read alongside the two academic papers below on MCP's actual failure modes (agent hijacking, spec gaps). We run roughly 15 MCP servers; the debate is about the layer we depend on daily.

A2M: Trace-Optimized Agent Hijacking in the MCP EcosystemarXivLaizhen Li et al. · arXiv (AACL-IJCNLP 2026) · 2026-09-22

A two-stage black-box attack that optimizes third-party MCP tool metadata and execution-trace-refined outputs to hijack which tool an agent selects, a semantic supply-chain risk distinct from a compromised server. [31]

Why this matters: A concrete mechanism behind the pin-third-party-MCP-servers guidance we already carry: this attack works by poisoning tool descriptions, not by taking over the server process.

Trust inversion and its exploitation: A threat model of the Model Context Protocol for agentic AISemantic ScholarM. Q. Sambo et al. · Journal of the Nigerian Society of Physical Sciences · 2026-09-21

Formal threat model of MCP's capability negotiation and dynamic tool discovery, showing how server-originated content can influence actions that execute under the client's own authority, a composition risk distinct from a compromised server. [35]

Why this matters: Names the mechanism behind A2M's hijack below: MCP's trust model lets a server describe itself, and the client acts on that description under its own permissions.

Persistent Billable State: Denial-of-Wallet Attacks and Defenses in Tool-Calling LLM AgentsSemantic ScholarJinqian Zhang et al. · arXiv · 2026-09-23

Describes a denial-of-wallet attack class: when a tool's return value is carried into later model turns, a compromised or malicious tool can keep getting re-metered, converting untrusted data into recurring victim-billed token spend. [36]

Why this matters: A cost-side failure mode worth checking for in any long-running agent loop we run unattended, alongside the usual data-exfiltration threat model.

Attack Success Rate Is Not a Number: On Measurement Validity in Agentic AI Security EvaluationSemantic ScholarChetan Pathade et al. · arXiv · 2026-09-21

Full-text meta-analysis of 259 agentic-security papers finds Attack Success Rate is not one metric but a family parameterized by six design choices that papers routinely leave unspecified, making headline percentages hard to compare. [37]

Why this matters: A caution for how we read any single attack-success-rate figure in this digest (including the 79% Auto Mode evasion rate cited last issue): check what the six design choices were before treating it as a fixed number.
