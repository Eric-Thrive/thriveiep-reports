Executive answer

Adopt the layering principle. Do not copy the four-file template.

The video is directionally right: long-running agents need stable rules, fresh working state, selective resource maps, and durable history. But Accommodation Engine, DEC1, and PM-Hub already have those layers. Their shared failure is lifecycle control—stale handoffs, ambiguous active worktrees, completed artifacts still marked active, and temporary project status embedded in durable instruction files.

The implementation target is freshness, routing, and proof—not more prose. Keep stable instructions as routers. Use one task-specific living control artifact. Record worktree identity and deterministic evidence in an existing dynamic-state surface. Preserve history without letting it govern the next action.
Keep

Progressive disclosure

Start small and retrieve deeper code, plans, schemas, and decisions only when the active task requires them.

Modify

One living task control

Use an existing plan, runbook, control artifact, or architecture snapshot—not a generic current.md in every repository.

Reject

Four automatic root files

Duplicate context surfaces add inference cost, competing authority, and another maintenance obligation.

The video’s model

Current state should outrank accumulated history.

The 23-minute video, Three OpenAI Engineers Shipped A Million Lines, uses OpenAI, Anthropic, and Arize examples to argue that agent failures often arise from poorly shaped context rather than raw reasoning limits. The presenter calls the continual maintenance of context layers “progressive context shaping.” The label is his synthesis; primary sources more often use progressive disclosure, context engineering, living plans, and structured handoff.

01 / STABLE

Instructions

Enduring rules, boundaries, architecture invariants, safety constraints, and source precedence.

02 / VOLATILE

Current state

Active outcome, decisions, questions, next action, blockers, stop conditions, and approval limits.

03 / RETRIEVAL

Context map

Routes to relevant code, design, schemas, plans, tests, evidence, and decision records.

04 / DURABLE

History

Completed work, superseded assumptions, failed approaches, rationale, commits, and evidence receipts.

The video’s practical sequence is sound: provide the intended outcome, relevant sources, action boundaries, first useful checkpoint, quality bar, and approval limits; then update a compact current-state record when discoveries change the work. Superseded assumptions move to history rather than remaining as active guidance.

Evidence beyond the video

Four research lines change how the idea should be implemented.

Context files

Evaluating AGENTS.md directly challenges “more guidance is better.” Developer-authored files produced only small average gains; generated files could reduce success; both increased inference cost. The practical implication is to repair concise human-owned authority rather than generate new summaries.

Position effects

Lost in the Middle shows that long context does not guarantee reliable use: relevant evidence can be handled worse when buried in the middle. Strong routing and selective retrieval matter even with large context windows.

Active retrieval

Coding Agents are Effective Long-Context Processors provides the counterweight. Coding agents can search and act over large repositories, so the goal is not a tiny static prompt—it is accurate entry routing, available source files, and task-directed retrieval.

Context rot

Repository instruction files are maintained software artifacts. They can refer to moved files, old status, and superseded architecture. Automated freshness checks are justified; ownership and lifecycle metadata are a practical governance inference.

Prior PM-Hub work

The existing research archive independently favors structure-preserving eviction over lossy compression, relevance-gated memory retrieval, executable contracts over prompt-only authority, fresh-agent tests, and validators instead of additional prose-heavy orchestration.

Combined conclusion: context shaping is repository governance, not prompt decoration. A context artifact must have an authority role, an owner, a freshness expectation, a supersession path, and a way to prove it still points to reality.
Repository application

The layers exist. The active-state lifecycle is weak.

Accommodation Engine
Good task routing · weak “continue current work” pickup

Already present: root instructions, scoped rules, C2A resource maps, code/PM-Hub knowledge routing, task plans/specs/runbooks, changelog, git history, and cross-product decision records.

  • Add a short entry route to the existing AGENTS.md: inspect branch/worktree/status and recent commits → identify the active task control → load its architecture anchor.
  • Mark the stale root plan and completed task plans superseded or complete.
  • Refresh or deprecate the stale three-layer KG guide.
  • Keep AGENTS.md as the Codex router and reduce duplicated durable guidance.

Do not add: CURRENT.md, another root map, a second decision log, or another Codex instruction file.

DEC1TEXTREDACTOR
Best compact snapshot · stale identity and contradictory status

Already present: root and scoped instructions, workflow playbook, architecture-state.json, architecture-changelog.jsonl, live-contract maps, control artifacts, plans, runbooks, and git history.

  • Extend architecture-state.json with branch, head SHA, worktree path, active controls, blockers, owner, last real-path proof, status, and supersededBy.
  • Run the existing architecture checkpoint on the actual active integration worktree.
  • Move obsolete “still blocking” project status out of AGENTS.md and record its resolution in state/changelog/control artifacts.
  • Add a lifecycle validator that flags multiple active controls for the same surface.

Do not add: CURRENT.md or another narrative index. Do not clean or consolidate divergent/dirty worktrees without owner review.

PM-Hub
Strongest router and decisions · stale handoff and priorities

Already present: AGENTS.md, _MANIFEST.md loading profiles, priorities, session handoff, decision records, changelog, session archive, structural KG, and semantic search.

  • Resume updates to the existing handoff and priorities instead of introducing another current-state file.
  • Reconcile and index current C2A artifacts.
  • Preserve _MANIFEST.md as the loading router and decisions as the rationale layer.

Do not add: a second current-state surface, project map, decision log, or search layer.

Recommended operating pattern

A living control loop for substantial AE and DEC1 work

Entry identity

Record repository, worktree path, branch, base/head SHA, and dirty-state summary.

Authority

Name governing instructions, task control, schema/spec precedence, approval boundaries, and explicit exclusions.

Frozen gate

Define the deterministic gate before code, record the failing result, and freeze it during implementation.

Early evidence

Produce the smallest real result capable of invalidating the plan before expanding scope.

Active slice

Keep outcome, current card/slice, next action, open questions, blockers, and stop conditions explicit.

Event update

Revise state only when a decision, authority, blocker, worktree, gate, or next action changes.

Finish proof

Require a passing deterministic gate plus execution through the last safe real boundary with positive evidence.

Closeout

Mark the active control complete or superseded, refresh the snapshot, and leave one unambiguous next action.

For a six- or ten-hour run: require recoverable changes, correct worktree isolation, frozen tests, explicit protected-data rules, no unapproved external writes, and stop conditions for repeated gate failure, authority conflict, or unexpected scope expansion. Duration is not the safety mechanism; bounded authority and observable evidence are.

The operational examples are predominantly vendor-authored 2025–2026 reports. They are authoritative about what the vendors built and observed, but weak evidence for causal productivity or transfer to ThriveIEP. The strongest independent challenge is the controlled AGENTS.md study, supported by peer-reviewed long-context evidence. Repository findings are high-confidence point-in-time observations, but active branches and worktrees can change rapidly.

Appraised distribution: 0 HIGH, 3 MODERATE, 4 LOW, and 8 VERY LOW under the research archive’s causal-evidence rubric. “Very low” does not mean an official document is unreliable about its own design; it means it is not a controlled study capable of supporting generalized causal claims.
